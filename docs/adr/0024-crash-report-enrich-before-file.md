# ADR 0024: Crash workflow — enrich before file, disposition routing to epics

**Status:** Accepted
**Date:** 2026-07-22

**related-files**: scripts/crash-report.js, .crash-report/known-noise.yml, .claude/skills/crash-report/SKILL.md, .claude/skills/crash-backtrace/SKILL.md, .claude/skills/README.md, docs/dev/crash-reports.md, tests/scripts/unit/crash-report.test.js

Supersedes [ADR 0006](0006-per-issue-crash-enrichment.md). The weekly Roku CSV carries only the crashing function signature, **not the exception code** — and the exception code (`&h29` too-many-task-threads, `&h23` execution timeout, `&hec` `'Dot'`-operator) is precisely what decides whether a crash is a small-scoped bug or an architectural class with no per-site fix. ADR 0006's file-first model filed issues straight off the CSV and enriched per-issue *afterward* via a separate `/crash-backtrace` skill, which meant deciding a crash's fate *before* knowing what it was — so architectural-class noise (a big-library `&h29`, a server-timeout `&h23`) got filed as standalone issues and had to be walked back. This ADR reorders the workflow to **enrich before file**: `stage` writes a local worksheet (every crash `pending`; a cheap mechanism hint — `task-launch` / `network` / `other` — only *orders* which backtrace to pull first, and never authorizes a file); `enrich` folds in the dashboard backtraces the user pastes, extracts each `&hNN`, source-maps the frames, and routes each crash to a **disposition**; `file` performs the GitHub writes. `/crash-backtrace` is deprecated (folded into the `enrich` phase); its `enrich-issue` subcommand survives only as a legacy escape hatch for a pre-migration already-filed issue.

Three dispositions live in a routing table at [`.crash-report/known-noise.yml`](../../.crash-report/known-noise.yml), keyed by exception code **plus context**: **`file`** (a scoped bug → a new per-signature `[crash]` issue, born enriched); **`aggregate`** (a known architectural class → one flat record comment per `file·function·line·version` **upserted** onto a class **epic**, keyed by a hidden marker with an embedded JSON data block as the source of truth, so a later run edits the existing record instead of duplicating — distinct lines are never auto-merged, occurrence stats accumulate, and the machine only ever rewrites comments it owns, never the human-authored epic body); and **`watch`** (accepted noise → counted, silent until a spike). Routing is by code alone for `&h29`/`&h23` (they are the class regardless of which site tips it), but `&hec` routes to the init-race epic **only** when it is `init()` + `m.global.constants` — bare `&hec` elsewhere is an ordinary scoped null-deref (that asymmetry is why the init-race pattern gates on function + snippet too). Three epics were seeded: #728 (big-library `&h29`), #729 (server-timeout `&h23`), and #103 promoted from a `watch` tracker to the `&hec` init-race epic.

The load-bearing decision, reached by dogfooding: **a backtrace is required before *every* disposition — nothing files or aggregates without one.** An earlier draft let `other`-mechanism crashes file *without* a backtrace to save dashboard clicks, but that reintroduced ADR 0006's flaw — a compute-bound `&h23` timeout can hide behind an ordinary-looking line the mechanism heuristic won't flag, so the heuristic is a safe *ordering* signal but an unsafe *authorization* signal. Alternatives ruled out: keeping the file-first split (rejected — it decides before it knows); the `file-ready` shortcut that files without a backtrace (rejected — files on a guess, and issues born without a backtrace are less useful to the fixer); filing per-signature issues for architectural classes (rejected — that is the noise the epics exist to prevent); and body-table accumulation on epics (rejected — it would make the machine rewrite a human-authored block; per-record comments keep the human/machine boundary clean). The cost — a dashboard click per new signature, within Roku's 7-day backtrace retention window — is accepted; dedup means only genuinely new signatures need a pull each week, and every filed issue ends up with a confirmed exception code + full backtrace + locals.
