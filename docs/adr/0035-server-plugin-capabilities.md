# ADR 0035: Features that need a server plugin are gated by a per-sign-in capability check; each capability chooses its own failure policy

**Status:** Accepted
**Date:** 2026-09-14

**related-files**: `source/utils/serverCapabilities.bs`, `components/data/jellyfin/JellyfinServer.xml`, `components/home/Home.bs`, `components/ItemDetails.bs`, `source/api/ApiClient.bs`, `source/utils/buttonOverflow.bs`, `tests/source/unit/utils/serverCapabilities.spec.bs`, `tests/rta/lib/jellyfin.js`, `docs/user/jellyfin-server-plugins.md`

Some features depend on what an admin INSTALLED on the server rather than on its version, so `apiVersion` cannot gate them. Manage Subtitles (#750) is the first: with no subtitle provider plugin every search returns an empty success, so the button was a dead end. The mechanism is shared. Each capability is one three-state string field on `JellyfinServer` (`""` unknown / `available` / `unavailable`), so "not checked yet" is distinct from "checked, none installed", and `session.server.Delete()` resets it on a server switch. It is checked once per sign-in from Home's first run (Home is remounted on every sign-in, so a plugin installed since the last check appears without restarting the app), and again by a consumer that finds it still unknown. A failed check is never stored, so it is retried rather than remembered. For subtitles the check is `GET /Libraries/AvailableOptions`, whose `SubtitleFetchers` lists installed subtitle providers: unchanged from 10.7.0 through 12.0 and authorized for any signed-in user (read in `LibraryController` and its policy handler; confirmed live against the 12.0 demo). A late answer inserts the button into a row that is already built, with focus carried by button ID through `buttonOverflow.bs`.

What a consumer does with a FAILED check is deliberately NOT part of the mechanism. It is decided per capability by asking what happens when a user reaches the feature and the plugin is absent: fail open only when that degrades safely and explains itself; fail closed when it would error confusingly, silently not work, or do something that cannot be undone. Subtitles fail open (`shouldOfferSubtitleSearch`), because an empty search explains itself and changes nothing, while hiding a working feature on a network blip is worse. Rejected: a boolean (cannot say "not checked yet"); the admin-only `/Plugins` endpoint (non-admins can hold the button); a module-wide fail-open default (right for subtitles, wrong for a plugin whose absence misleads or does harm); folding in Quick Connect and the JellyRock companion plugin — Quick Connect is probed before login with no auth, and the companion plugin is re-probed per reconnect on `RemoteControlTask`'s Task thread, so both are correctly placed. Limit: a provider installed without credentials still counts as available, and the panel's empty-state message covers that case.
