# ADR 0042: A PR title's type decides where the change lands in the changelog

**Status:** Accepted
**Date:** 2026-09-24

**related-files**: `scripts/lib/pr-title.js`, `scripts/changelog-syncer.js`, `scripts/lint/pr-body-check.js`, `.github/pull_request_template.md`, `.claude/skills/pr/SKILL.md`, `docs/admin/changelog.md`

The repo keeps squash-merging, so a PR title is the first line of its commit on `main`, and the title's type (`fix:`, `feat:` …) is the one input that places the change in `CHANGELOG.md`. The types and their sections are defined once, in `TITLE_TYPES` in `scripts/lib/pr-title.js`. Three consumers read that table: `changelog-syncer.js`; `pr-body-check.js`, which fails a PR title without a known type in the `precheck` job, a required status check on `main`; and the `/pr` skill. The sections are Added, Changed, Fixed, Removed and Dependencies. Tooling types (`chore`, `ci`, `build`, `docs`, `test`, `style`) stay out of the changelog. `refactor` stays in, under Changed, because a refactor can regress and developers read the changelog too. The Security and Deprecated sections are dropped; `security:` files under Fixed. A scope is kept in the line (`(skills) …`) and must not be blank. `changelog-syncer.js` reads the PR's **current** title for the PR's own squash commit, matched by the `mergeCommit` SHA, so a wrong type is fixed by editing the PR title and re-syncing, until the release is cut.

**Considered and ruled out.** *Keep guessing a section from the title's words.* The old `startsWith` checks dropped "Cinema mode: …" as `ci`, filed "Fixture loading …" under Fixed, and moved "fix: … security settings …" to Security. An untyped title now goes to Changed, and CI stops untyped titles before merge. *Let labels decide the section.* Outside contributors can't set labels, and a PR can honestly carry several, so labels stay a judgment call in `/pr`, for sorting in the GitHub UI, and only the `dependencies` label is read by the changelog. *GitHub's `Rebase and merge`, or merge commits.* The first would put every branch commit, including pre-push auto-fix commits, into the changelog; merge commits would need `changelog-syncer.js` to follow only `main`'s first-parent history. *Keep the Docs checklist in the body.* The body is the permanent commit message, so the checklist was noise in `git log`, and tooling already enforces its items; reviewer-only detail goes in a `/pr`-owned review-notes comment, which also holds the render marker. **Evidence:** rendering v2.29.1..HEAD with the old and new `changelog-syncer.js` differs only in #984, which is untyped and moved from Added (guessed from "new") to Changed. The first new render listed every PR twice, because journal-sync commits also end in `(#N)`; the `mergeCommit` match fixed that, and `changelog-syncer-pr-title.test.js` now guards it.
