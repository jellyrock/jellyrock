# ADR 0025: Gradients render as stretched tinted ramp posters, not Rectangle stacks

**Status:** Accepted
**Date:** 2026-08-08

**related-files**: `components/ui/Gradient.bs`, `components/ui/Gradient.xml`, `scripts/generate/gradient-assets.js`, `images/gradients/fade-v.png`

Continuous shading (gradients, fades, dimmers) renders as a single Poster stretching a tiny generated alpha-ramp bitmap (`4×270`, white, linear `255`→`0`), tinted via `blendColor` — not as a stack of per-step Rectangle nodes. The Rectangle approach was the original design (zero texture memory) but hardware measurement on a device with a 720p UI (Roku Stick `3600X`, #777) disproved its economics twice over: `1–2px` strips alias into visible bars/gaps under the FHD→HD autoscale (the bug), and each rebuild cost `37–77ms` of render-thread time versus `0–2ms` for the poster (three runs each, `~560ms`→`~8ms` across a boot→details sequence). The feared texture cost does not materialize: allocations follow the *decoded source* dimensions, not the displayed size (verified via `r2d2_bitmaps` — `4×270` assets allocate `~36KB` each regardless of stretch, `~110KB` total shared across all instances by URI, 0.22% of that device's `50MB` budget). This is not the removed anti-pattern of full-screen gradient bitmaps (those decoded at `~2.3MB` each; for scale, our own `splash-screen_fhd.png` allocates `8.36MB`); Roku OS itself ships its player pause shade as a stretched `3×1082` bitmap. Stretched ramps are also scale-independent at every UI resolution, where grid-aligned Rectangle strips (the runner-up fix) stay coupled to specific scale factors and would re-band at SD.

Accepted constraint: `Gradient` fades one color out to nothing, with the transparent end in either position — a single `blendColor` cannot carry a second hue, so a fade between two *visible* ends fires a debug `m.log.warn`. The transparent end's RGB is ignored rather than compared, because callers assign the two colors in separate statements and the field observer sees the half-updated state; comparing the two RGB values warned on correct usage until that was fixed. Every call site conforms. Of the four generated ramps, `fade-h180` currently has no call site (it needs `direction="horizontal"` with `rotateDegrees=180`/`270`); it ships for API symmetry at 538 bytes packaged and zero texture memory until used. Assets are committed but generated deterministically by `scripts/generate/gradient-assets.js` (`npm run gradients:build` / `gradients:check`, pre-push wired like the icons pipeline). Constraints worth re-evaluating: a future design needing a genuine two-hue gradient (add a second ramp asset class or a dual-poster composite), and Rectangle nodes remain correct for flat fills.
