# ADR 0046: A playback start's wait is a Promise per start

**Status:** Accepted
**Date:** 2026-09-27
**Partially supersedes:** [ADR 0044](0044-spinner-by-kind-of-wait.md) (app waits end by their Promise, not by name)

**related-files**: `source/utils/appWaits.bs`, `source/enums/LoadingKind.bs`, `source/utils/loadingStages.bs`, `source/constants/timeouts.bs`, `components/JRScene.bs`, `components/JRScreen.xml`, `components/manager/QueueManager.bs`, `components/video/VideoPlayerView.bs`, `components/music/AudioPlayerView.bs`, `components/ItemDetails.bs`, `tests/rta/specs/playback-start.spec.js`, `docs/architecture/navigation.md`

A playback start runs from a press on one screen to a player on another, so its wait cannot live on either screen ([ADR 0044](0044-spinner-by-kind-of-wait.md) named these "app waits" and deferred them). Every start now opens a `PLAYBACK_START` app wait: `QueueManager.beginPlaybackStart()` asks the scene for a Promise (`JRScene.beginAppWait`, through `callFunc` only), the scene shows the spinner and its 8 s / 30 s stage text until that Promise settles, and the player that mounts takes it (`takePlaybackStart()`), resolving it when its stream loads and failing it on a failed load or in teardown. The first settle wins and later ones do nothing, so every exit path ends it without checking. Leaving the screen the start was pressed on before any player exists fails it (`appWaits.leftBehind()`; a screen that plays declares `JRScreen.isPlaybackScreen`) and stops the Play all / shuffle build, which only reads; a time limit (`timeouts.PLAYBACK_START_LIMIT_MS`, outlasting a live open plus the load's other requests) fails and logs one nobody ended. A start still hides the screen it was pressed on, now by `opacity`, which the router never touches, and no longer disables the remote. Measured on an Ultra against 12.0 with the answer held 8 s (2026-09-26), before this: Back mid-start from a grid left the plain spinner up over the grid and then Home, 35 s and counting, with the scene holding the remote disabled; Back during a Series "Play all" let the player launch on the grid once the episode list arrived. `playback-start.spec.js` gates both, and fails 4/4 on the old code.

**Why a Promise and not a name.** ADR 0044 planned app waits ended by name. A name cannot tell two starts apart: the player a channel switch replaces used to need an `isSwitchingChannel` flag so that its own stop did not end the next channel's spinner, and every handover would need a guard like it. With one Promise per start, code holding a start can only settle that start. **Ruled out:** ending by name (above); a plain string token per start (the same identity, but without the promise library's settle-once and `onFinally` delivery, and a second completion vocabulary beside the promises the render thread already uses, [ADR 0012](0012-promise-native-interface-fetchres-exception.md)); keeping the plain spinner and stopping it in the player's teardown (it stops whatever spinner is up, including the next channel's). Screen waits keep ending by name, which is safe there because a screen can only reach its own. The session-change and buffering kinds, and photo launches, stay on the plain spinner until they are moved.
