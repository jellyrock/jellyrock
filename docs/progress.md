- **`releaseRef` swallows a failed DELETE, so a leaked lease blocks the device for 15 minutes — and a caller with high lock churn turns that from rare into likely.** [`device-lock.js`](../scripts/device-lock.js)'s release warns (`could not release the lock; the lease will expire on its own`) rather than retrying, which is correct for a tool that takes the lock ONCE per run — every consumer but one. `measure:calibrate` takes it about **twenty-five times** per run (a deploy plus a child per block, plus the restore), and it is the only caller where a leak lands MID-run instead of as a harmless last line. **Observed twice on 2026-08-18:** harmlessly at the end of the `.178` matrix, then at block 4 of 12 of a replication run, where the next acquire found our own just-exited child still holding the ref and a 45-minute run died on it. Nothing was wrong with the device — `npm run device:release` cleared it immediately and `rta:restore` verified clean. **Already absorbed locally** (the calibration driver now waits the lease out for 17 min rather than dying, and says what it is waiting for), so this entry is about the SHARED half. **Fix shape:** retry the DELETE two or three times inside `releaseRef` before falling back to the warn — a transient GitHub API failure is exactly what a retry is for, and the current behavior makes every caller pay a 15-minute lease for it. Deliberately not folded into the calibration branch per `isolate-the-fix`: that file is shared with `rta-run.js`, `rta-restore.js`, the screenshot orchestrator and the demo runner, and changing release semantics for all of them to serve one caller's unusual churn is the wrong blast radius for a bug that caller can absorb.

- **`/crash-report`'s occurrence threshold silently starves the architectural epics of evidence, because it fires before the disposition is knowable.** [`applyThreshold()`](../scripts/crash-report.js) drops any signature below `min-devices=2` OR `min-dates=2`, and only surviving rows are offered for backtrace enrichment — but the exception code that routes a crash to `file` / `aggregate` / `watch` lives *only* in the backtrace. So a crash cannot be known to belong to an epic until after the gate that already excluded it. Observed 2026-08-21: the 08-15..08-20 report carried four `&hec` themed-init crashes (`JRLabel:5`, `JRPlaceholder:11`, `ScrollingLabelSmaller:2`, `VideoProgressBar:5`), each 1 date / 1 device, so all four were skipped and **epic [#103](https://github.com/jellyrock/jellyrock/issues/103) received nothing** — even though a manually-pulled backtrace confirmed `JRPlaceholder:11` as `&hec` + `init()` + `m.global.constants`, a textbook member of that class. The threshold's real purpose is to stop noisy *filing* (a new `[crash]` issue per singleton); an epic *record* comment carries no such risk, since records are upserted per `file·function·line·version` and accumulate. Net effect: the epics under-count exactly the long-tail classes they exist to aggregate, and a low-frequency-but-persistent architectural crash looks quieter than it is. **Fix shape (needs a design call, not a one-liner):** either exempt signatures whose `pkgPath`+`function` already appear on an epic's existing records from the threshold, or split the gate into `file-threshold` vs `aggregate-threshold` with the latter at 1/1. Interim workaround is `--min-dates 1` when the intent is epic evidence, which is a manual step nobody will remember. Surfaced running `/crash-report` while closing epics #728/#729.
- **~~`screen-load`'s `contentFills` / `textureFills` are COUNTS that `unitFor` answers `'ms'` for~~ — 🚨 WITHDRAWN 2026-08-22, THE CLAIM WAS FALSE AND WAS NEVER CHECKED.** Those three fields (`fills`, `contentFills`, `textureFills`) have been in `screen-load`'s `workload` list since [#813](https://github.com/jellyrock/jellyrock/pull/813) and print with no unit at all; `unitFor('contentFills', screenLoad)` returns `''`. The entry was filed off a *reading* of the `cell-load` defect and generalized to a sibling family without running `unitFor` against it — the same verify-don't-assume failure the `cell-load` fix had explicitly avoided by running it. **The defect class was real and the family was wrong.** The actual second instance is [`home-latest-rows`](../scripts/measurements.js), which emits `sizeCalls` and `sizeDrains` — genuine counts that answered `'ms'`, so `measure:report --field sizeCalls` headlined a call count as milliseconds. Fixed by declaring them in `counts`, and it was found by a **gate rather than by a reader**: a new test asserts every numeric field a family emits is classified (in `workload`, in `counts`, or a duration by name), which is the complement of the check that only verified `counts` entries are emitted. Numeric fields are decidable statically because the patterns capture them with `\d+` and dimensions with `\S+`, so it needs no allowlist. That test also caught two flaws in its own first draft — `loadMsMax` is a duration an end-anchored name check rejected, and `loadMsCount` is a count whose name contains `Ms`, so `counts` has to be consulted before any name heuristic.
- **`measure:compare` can't compare any A/B whose independent variable isn't code, so the repo's own comparison tool is unusable for a whole class of real experiments.** It refuses two arms sharing a commit — a correct guard against the common mistake (an uncommitted change leaves both arms on the same SHA) — but that also rules out every experiment where the thing varied is *not* the checkout: server configuration, device state, network conditions, user settings. Hit directly 2026-08-21: the Home row-count campaign varied `LatestItemsExcludes` on the Jellyfin server with the build held **constant** across all 12 alternated blocks, which is exactly the design the guard forbids. The comparison had to be hand-rolled — reading `.device-runs/measure/measurements.jsonl` directly and implementing a Mann-Whitney in a throwaway script — so that campaign has no `measure:compare` provenance, no `seriesConsistency` check, and no reusable record of how it was decided, even though it produced the cost model the whole project now rests on. **Why it matters beyond one campaign:** arms that vary server configuration or device state are the natural shape for scaling questions (row count, library composition, connection speed), which are precisely what the measurement subsystem exists to answer. **Fix shape:** let an arm declare a non-code independent variable — `--variable=server-config`, or an `--allow-same-commit` that *records what differed* rather than refusing — so the guard keeps catching the accidental case while the deliberate one stays inside the tool. Surfaced running the Home row-count and `Limit` sweep campaigns.
- **Nothing asserts that a BSC plugin is actually REGISTERED, so deleting one line from a `bsconfig` plugins array silently disables it.** [`scripts/bsc-plugins/`](../scripts/bsc-plugins/) holds seven convention plugins, three of them at **Error** severity ([`no-raw-run`](../scripts/bsc-plugins/no-raw-run.cjs), [`no-task-fanout`](../scripts/bsc-plugins/no-task-fanout.cjs), [`callfunc-interface`](../scripts/bsc-plugins/callfunc-interface.cjs)). Each is enforced only by its entry in [`bsconfig.json`](../bsconfig.json) / [`bsconfig-prod.json`](../bsconfig-prod.json), and nothing — no test, no lint step, no CI job — checks that the entry is still there. Removing it leaves the plugin file, its whole test suite, and every doc reference intact and passing, while the rule stops being enforced: the failure is total, silent, and green. Surfaced reviewing #846, where the same *class* of risk in `no-task-fanout` itself (a bare-only match on `launchTask`'s `callee`, which moving `tasks.bs` into a namespace would have disabled wholesale) was closed in that PR — this is the wider surface it pointed at. **Fix shape:** a Vitest case enumerating `scripts/bsc-plugins/*.cjs` against both configs, with an explicit allowlist for the deliberate asymmetries (`callfunc-interface` is registered in `bsconfig.json` only; `roku-log` / `translation-keys` are wired per build), so an intentional exclusion stays possible but an accidental one fails.
