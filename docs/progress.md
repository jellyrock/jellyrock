- **`/crash-report`'s occurrence threshold silently starves the architectural epics of evidence, because it fires before the disposition is knowable.** [`applyThreshold()`](../scripts/crash-report.js) drops any signature below `min-devices=2` OR `min-dates=2`, and only surviving rows are offered for backtrace enrichment — but the exception code that routes a crash to `file` / `aggregate` / `watch` lives *only* in the backtrace. So a crash cannot be known to belong to an epic until after the gate that already excluded it. Observed 2026-08-21: the 08-15..08-20 report carried four `&hec` themed-init crashes (`JRLabel:5`, `JRPlaceholder:11`, `ScrollingLabelSmaller:2`, `VideoProgressBar:5`), each 1 date / 1 device, so all four were skipped and **epic [#103](https://github.com/jellyrock/jellyrock/issues/103) received nothing** — even though a manually-pulled backtrace confirmed `JRPlaceholder:11` as `&hec` + `init()` + `m.global.constants`, a textbook member of that class. The threshold's real purpose is to stop noisy *filing* (a new `[crash]` issue per singleton); an epic *record* comment carries no such risk, since records are upserted per `file·function·line·version` and accumulate.
